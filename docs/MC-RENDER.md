# 网页按 MC 方块模型画方块（P3）

这份文档说明网页怎么读玩家自己的 Minecraft 客户端 jar、按方块模型把方块画出来，和 MC 比对的结果，已知和 MC 不一样的地方，以及还没做的事。对应版本：Minecraft 26.1.2（NeoForge 开发环境，DataVersion 4790）。第一部分做了读 jar、模型、网格和 P3-001 对比；第二部分加了打开鲸图、光照、箱子和床的模型、含水方块和 P3-002 对比。

## 1. 版权规矩（硬规矩）

- Mojang 的贴图、模型、blockstates 文件**不进 git、不打包进网页**。网页只在运行时读玩家自己选的 jar，读到的东西只存在玩家自己浏览器的 IndexedDB 里。
- 提交的测试只用自己造的小 jar（`web/tools/mc-testjar.mjs`：几张纯色贴图 + 手写的模型 JSON）。
- 用真贴图做出来的截图、对比图只放 `tmp/`（不提交）。
- 没选 jar 时的兜底颜色和像素纹理（`17-mcfallback.js`）由我们自己设计，没有从 MC 的文件或代码里抄颜色表、图片或模型。木板、木纹/端面、上下门板、铁灰框和琥珀/灵魂灯芯由确定性规则生成 16×16 RGBA（`v3:fallback/*`），不增加内嵌 Mojang 资源。云杉/白桦树叶、睡莲这类 MC 写死在代码里的颜色，也没有抄，用平原的树叶颜色代替（见第 6 节）。
- jar 路径从命令行参数或环境变量 `MC_JAR` 传，代码里不写死路径。

## 2. 怎么用

### 查看页（开发用）

`node build.mjs` 会生成 `dist/mcview.html`（约 0.8 MB，不带 `web/assets/`）。打开以后：

- 「选 MC jar…」：选客户端 jar（比如 `.minecraft/versions/26.1.2/26.1.2.jar`）。只读需要的文件（约 2.2 MB），存进 IndexedDB，下次打开自动用，不用再选。「忘掉 jar」清掉缓存。
- 「打开鲸图…」：打开鲸图 PNG、`.schem`、dump JSON（docs/FORMAT.md §4）或方块区域 JSON（格式见下），也可以直接把文件拖进页面（拖 `.jar` 就是换 jar）。读不出来时状态栏显示鲸图读取器（`V3.share`）给的中文提示，比如普通图片会说「这张图里没有方块数据……请让对方『发送原图』」，原来画着的东西不动。「示例」是内置的一小块示例场景（只有方块名字，不含 MC 的任何文件）。
- 没选 jar 时也能打开鲸图，用自己的兜底颜色、像素纹理和形状画。
- 「平滑光照」：开关 AO。「光照」：开关天光和方块光（第 4 节）；关掉就处处当正午露天的满亮。
- 鼠标拖动旋转、滚轮缩放、右键平移（和 studio 一样的 `V3.Orbit`）。

地址参数（测试和对比工具用）：

| 参数 | 意思 |
|---|---|
| `model=<url>` | 要画的文件：鲸图 PNG、`.schem`、dump JSON 或方块区域 JSON（按内容判断格式，不看扩展名） |
| `jar=<url>` | jar 的地址；`cache=1` 时读完存进 IndexedDB；`cache=0` 不读也不存缓存 |
| `cam=x,y,z,yaw,pitch[,fov]` | 用 MC 的相机：脚的位置（世界坐标）、MC 的 yaw/pitch（度）、竖直视野（默认 70）；这时不能拖动 |
| `w=…&h=…` | 画布固定大小（不跟窗口走） |
| `compare=1` | 对比模式：没有工具栏和提示，背景透明，默认开雾 |
| `ao=0` | 关平滑光照 |
| `light=0` | 关光照（处处满亮，和第一部分一样） |
| `fog=1` / `fog=0` | 开/关 MC 的白天雾（`rd=8` 是视距，默认 8） |
| `bright=…`、`mip=…` | 整体亮度倍数（默认 1）、最多用几级 mipmap（默认 4，和 MC 默认一样） |

页面上挂了 `window.__mcview`（测试用）：`ready`、`stats`、`warnings`、`pack`、`fog`、`model`（打开的文件名、大小、世界坐标）、`lastError`、`setModel(m)`、`openModel(bytes, name)`、`openModelUrl(url)`、`loadJar(bytes, save)`、`loadJarUrl(url, save)`、`clearJar()`、`setCamera(c)`、`snapshot()`、`info()`。

### 输入格式

鲸图 PNG 和 `.schem` 用 `V3.share.read` 读，dump JSON 用 `V3.share.fromDump`（都是 fmt-js 的模块，和模组、`web/tools/share.mjs` 同一份代码）。另外 `V3.mcmesh.normalize` 还接受：

1. `{size:[W,H,L], palette:[状态字符串…], cells:[调色板编号…], blockEntities:[…]}`，`cells` 是平铺数组；
2. 同上但 `cells` 是游程 `[[个数, 编号], …]`；
3. 探针 `/region` 的结果 `{origin, size, palette, blocks, blockEntities}`。

格子编号 i = x + z×W + y×W×L。调色板是完整的方块状态字符串，比如 `minecraft:oak_stairs[facing=east,half=top,shape=straight,waterlogged=false]`。

世界坐标（第 (0,0,0) 格在世界里的位置）：鲸图按 docs/FORMAT.md §3.2 用 `Metadata.Xiaojingyu.Origin + Offset`；没有 Origin 的文件就当它在 `Offset`；探针区域用 `origin`。世界坐标只影响随机朝向的方块（草方块、石头……）和植物的随机偏移，没有 Origin 时这些和游戏里对不上，不算错（见第 6 节）。

## 4. 和 MC 对齐的地方（都对着 26.1.2 的源码核对过）

- **blockstates**：variants 的键按属性匹配（`""` 匹配所有状态）；multipart 的 `when` 支持 `OR`、`AND`、`a|b`、`!a`，没有这个属性就算不匹配；一个状态能匹配上 variants 就不再看 multipart。状态字符串缺属性时先严格匹配，匹配不上再宽松匹配并给提示。
- **随机变体**（石头、草方块、泥土、沙子等 38 种 blockstates，multipart 里有竹子、紫颂植物、火）：用和 MC 一样的位置种子（`Mth.getSeed`）和 `java.util.Random`，结果和 JDK 跑出来的逐个对过；门、高草这类上下两格的方块用下半格的位置。
- **26.1 的新写法**：variant 的 `z` 旋转、元素旋转的 `x/y/z` 欧拉角写法、贴图写成 `{"sprite": …, "force_translucent": true}`。原版 26.1.2 只用到了最后一种（玻璃、染色玻璃、红石线），另外两种也支持（给模组和资源包）。
- **烘焙**：每个面的顶点顺序、没写 uv 时的默认 uv、面的 `rotation`、`uvlock`（贴图保持世界方向）、元素旋转和 `rescale`、模型整体 x/y/z 旋转、cullface 跟着模型一起转、厚度为 0 的元素只保留该保留的面，都按 `FaceBakery` / `UnbakedCuboidGeometry` 的写法。
- **分层**：和 26.1 一样按贴图算：面用到的那块贴图里有完全透明的像素 → cutout；有半透明像素 → translucent；`force_translucent` → translucent；否则 solid。所以 26.1 的玻璃在半透明层（不是老版本的镂空层），火把是一个实心的小方柱（26.1 的火把模型就是这样）。
- **剔除**：按 `Block.shouldRenderFace`：相邻方块那一面的形状把这一面完全盖住才剔除（用每个状态每个方向 16×16 的遮挡图来算，所以半砖、楼梯也对）；同种玻璃/冰/粘液块/蜂蜜块之间、连上的玻璃板和铁栏杆之间、同种液体之间不画；树叶之间不剔除（MC 默认「镂空树叶」开着）；门、活板门这类不挡光的方块不挡别人。
- **明暗**：按朝向乘：上 1.0、下 0.5、南北 0.8、东西 0.6；元素 `shade: false` 的面不乘。
- **平滑光照（AO）**：照搬 `BlockModelLighter` 的算法（每个顶点看三个邻格和角上的格子，`shadeBrightness`：完整碰撞箱的方块 0.2，其他 1.0；玻璃类 1.0）。模型 `ambientocclusion: false` 的方块、会发光的方块（萤石、火把、点着的熔炉等）不做 AO，和 MC 一样。
- **光照**（`19-mclight.js`，第二部分加的）：在整个区域里按 MC 的规矩算天光和方块光（0–15），再按正午的光照图换成亮度。区域外面一律当露天的空气（天光 15，没有方块光）。
  - 挡光（`lightDampening`）：完整不透明的方块 15；树叶 1；有色玻璃 15；玻璃、染色玻璃 0；水、岩浆、气泡柱、海带、海草和含水的方块 1；潜影盒 1；其他不完整的方块（栅栏、门、火把……）0；完整但不挡视线的（冰等）1。传播一格减 `max(1, 挡光)`。
  - 按形状挡光（`useShapeForLightOcclusion`）：半砖、楼梯、雪层、土径、耕地、阳光传感器、附魔台、末地传送门框架、讲台、切石机、活塞、幽匿感测体/尖啸体、书架架子：两格之间看这两个面的形状，合起来把整个面盖住就不过光。底半砖上面那格还是天光 15，下面那格 14，和游戏一样。
  - 天光从上往下照：每一列从顶上一直往下，碰到挡光不是 0 或者形状挡住的格子为止都是 15；再往旁边和下面扩散。
  - 方块发光：自己的表，数值照 26.1.2 的 `Blocks.java` 抄（火把 14、灯笼 15、魂灯笼 10、萤石 15、点着的熔炉 13、岩浆 15、红石火把 7、末地烛 14、海晶灯 15……，蜡烛 3×根数、海泡菜 3+3×个数、重生锚按充能、光源方块按 `level`、发光地衣、洞穴藤蔓、试炼刷怪笼、宝库按状态），一共六十多种；`waxed_` 的铜方块和不带蜡的一样。岩浆块、激活的幽匿感测体按 MC 的 `emissiveRendering` 满亮画。
  - 每个顶点的光：和 AO 一起算，照搬 `BlockModelLighter` 取邻格光的规则和 `LightCoordsUtil.smoothBlend`（邻格是 0 时用中间那格的光补上）、`smoothWeightedBlend`（不完整的面按面的大小加权）。不做 AO 的面：有 cullface 的取那一侧邻格的光，完整的面取面前那格，其他取自己那格（`prepareQuadFlat`）。水和岩浆取自己和上面那格里亮的。方块实体（箱子、床……）取自己那格。
  - 光照图：照搬 `lightmap.fsh`，正午的参数：天空 1.0、天空光颜色白、环境光 #0a0a0a（主世界）、方块光颜色 #ffd88c、方块光倍数 1.4（不算闪烁）、亮度选项 0.5（默认）。光照图存成 8 位颜色，两级之间线性插值（和 `sample_lightmap` 一样）。天光 15 → 1.0，14 → 0.91；完全黑的地方 0.094。
- **箱子和床**（`19-mcentity.js`，第二部分加的）：MC 用实体模型画，模型不在 JSON 里。我们照 26.1.2 的源码自己写：
  - 形状：箱子底座 14×10×14、盖子 14×5×14、锁扣 2×4×1（`ChestModel`）；大箱子的左右两半各 15 宽、挨着的那面不画；床是 16×16×6 的床垫加两条 3×3×3 的床腿，床头、床脚各一半，挨着的那面不画（`BedRenderer`）。盒子怎么展开贴图、每个面四个角的贴图坐标照 `ModelPart` 的规则（贴图 64×64）。
  - 朝向：箱子按 `facing` 绕竖轴转（`ChestRenderer`），左右两半按 `type`（MC 的 `ChestBlock.getConnectedDirection`：左半的另一半在 `facing` 顺时针转 90° 那边）；床先平放再按 `facing` 转。
  - 贴图：jar 里的 `textures/entity/chest/<种类>[_left|_right].png`（normal、trapped、ender、copper、copper_exposed、copper_weathered、copper_oxidized；`waxed_` 和不带蜡的同一张）、`textures/entity/bed/<颜色>.png`。贴图找不到（比如旧缓存、模组 jar）就退回原来的盒子。
  - 画法：单独一层（实体层），和 MC 的实体贴图集一样用最近点采样、不用 mipmap，alpha < 0.1 丢掉；明暗不用方块的四个方向，用实体的两盏灯（`Lighting` 的 `DIFFUSE_LIGHT_0/1`，`light.glsl`：上 1.0、下 0.4、南北 0.74、东西 0.50）；不做 AO；光取自己那格，大箱子和床取两半里亮的那格（MC 的 `BrightnessCombiner`）。
  - 圣诞节（12 月 24–26 日）MC 的箱子换成礼物贴图，我们不换。
- **含水方块**（第二部分加的）：`waterlogged=true` 的方块，还有海带、海草、气泡柱（MC 里它们一直泡在水里），在方块自己的模型之外再画一格静止的水（平顶 8/9 高，上面也是水就满格），颜色用群系水色，放半透明层。哪些面不画照 MC 的 `FluidRenderer`：挨着同一种流体的面不画（含水方块也算水，和 NeoForge 默认的 `shouldHideAdjacentFluidFace` 一样）；方块自己在那一面是完整的遮挡面就不画（比如底半砖下面、楼梯背面；向上的面不看自己）；邻格那一面完整遮挡也不画（向上的面要水满一格才算）。光取这格和上面一格里亮的。
- **群系颜色**：草方块、草、蕨、灌木等用 jar 里的 `colormap/grass.png`，树叶、藤蔓用 `colormap/foliage.png`，取值的位置按平原的温度和湿度（从 jar 里的 `plains.json` 读），水用平原的水色。都是运行时从玩家的 jar 读，不写在代码里。
- **植物随机偏移**：花、草、高草、竹子等按 MC 的公式在格子里随机挪一点（看第 6 节的世界坐标问题）。
- **相机**：竖直视野；旁观模式下视野 = 70 × 1.1 = 77°（飞行加成）；眼睛高度 1.62；近裁剪面 0.05；MC 的 yaw/pitch 换成 three.js 的 `rotation.set(−pitch, π − yaw, 0, 'YXZ')`。对比时把视野从 70 扫到 80，差异在正好 77 的时候最小（5 张图都一样），说明这几项都对上了。
- **贴图过滤**：和 MC 26.1 一样，方块贴图用线性过滤 + 线性 mipmap（`LevelRenderer` 里的 `chunkLayerSampler`），着色器里照搬 `terrain.fsh` 的 `sampleNearest`：放大时把 UV 吸到像素中心，所以近处还是一格一格的清楚像素，只在像素边上留不到一个屏幕像素宽的过渡；缩小时正常走 mipmap（最多 4 级，和 MC 默认一样）。拼图集时每张贴图四周留 16 像素的边，边里填贴图边缘像素的延伸，mipmap 按每张贴图自己算（MC 的 `Stitcher` 也这样留边，选项是各向异性 2 时它留 32 像素；我们最多 4 级 mipmap，16 像素到第 4 级还剩 1 像素，够用）。MC 的另一种过滤 RGSS（选项 `textureFiltering:1`）没做，开发游戏用的是默认的 0。
- **雾**：MC 白天的雾：球面距离雾 + 圆柱距离雾（视距 8 时从 115.2 格到 128 格），雾色由维度的 `fog_color` 和群系的 `sky_color` 按视距混合，两样都从 jar 里读。对比模式默认开；平时看建筑默认关。

## 6. 已知和 MC 不一样的地方

按对画面影响从大到小：

1. **别的方块实体还是盒子**：箱子和床画真模型了（第 4 节）。还是盒子的：各种告示牌和悬挂告示牌、旗帜、头颅、潜影盒、饰纹陶罐、潮涌核心、铜傀儡雕像、瓶子草作物等（26.1.2 里 161 个 blockstates 的模型没有 elements，MC 用代码画）。按名字给大小、按朝向摆盒子，颜色取粒子贴图的平均色（旗帜按染料色）。告示牌上的字、旗帜图案都没有。箱子开着盖的样子（有人打开时）、圣诞节的礼物箱子也不画。
2. **光照只算正午、只看区域里面**：天光和方块光按 MC 的规矩在区域里算（第 4 节），但时间固定正午、天气晴；区域外面一律当露天的空气，所以贴着区域边、MC 里被外面的山或房子挡住的地方，网页会比游戏亮。方块光不闪（MC 的方块光颜色每帧有一点随机抖动，平均下来是 0）。区域里没有的方块挡不住光：抓的时候没抓到的屋顶、墙，网页当它是空气。
3. **没有粒子和动画**：火把、营火的火焰和烟是 MC 的粒子，网页没有。动态贴图（水、岩浆、火、海晶灯……）只用第一帧。
4. **含水方块里的水是简化的**：第二部分起会画（第 4 节），但和纯水一样是平顶 8/9。MC 的水面四个角按旁边几格的高度加权平均（`FluidRenderer.calculateAverageHeight`：实心的邻格不算，空气算 0 高），所以水旁边是空气时 MC 的水面会低一点（四周都是空气的一格水在 0.74 高，只有一边是空气就斜）；四周是实心方块或水时和我们一样。挨着别的方块时 MC 里的半格遮挡（比如底半砖旁边的水侧面）我们按「完整的面才挡」算。
5. **水和岩浆是简化的**：水面是平的（高度按 level 算，上面有同种液体就满格），不做 MC 那样四个角按邻居高度插值的斜面，也不按流向转流动贴图；液体不做 AO。
6. **颜色近似**：
   - 群系固定为平原，不做群系过渡（MC 默认按周围 5×5 群系平均）。
   - 云杉、白桦树叶，睡莲，接上了果实的瓜梗：MC 用写死在代码里的颜色，我们没抄，分别用平原的树叶色、树叶色 × 0.7、自己定的橙色代替。云杉、白桦树叶的颜色会偏。
   - 红石线按信号强度的颜色、瓜梗按生长阶段的颜色是我们自己定的渐变，和 MC 的颜色有差别。
7. **mipmap 的细节**：我们的 mipmap 是简单的按透明度加权的 2×2 平均。MC 26.1 按贴图的 `.mcmeta` 选不同的算法（花草 `strict_cutout`、树叶 `dark_cutout`、玻璃和红石线 `mean`，仙人掌等还有 `alpha_cutoff_bias`）。只影响很斜、很远的面。图集因为留边变大了：全部贴图（约 1100 张）拼出来是 2048×2048，加上 mipmap 约 22 MB 显存；一般建筑只用到几十张，图集很小。
8. **半透明排序**：我们把半透明的面按面中心从远到近排；MC 按区块分段排。半透明的东西叠在一起时，个别角度谁盖谁可能不一样。
9. **AO 的两个判断是近似的**：MC 按碰撞箱算 `shadeBrightness`、按 `isViewBlocking` 和透光度判断挡不挡光；我们都按「模型是不是完整方块」（挡光再去掉玻璃、树叶这类看得穿的）。绝大多数方块结果一样；模型是完整方块但碰撞箱不是的方块（比如细雪）边上的阴影会差一点。
10. **随机朝向要世界坐标**：石头、草方块等的随机朝向、花草的随机偏移都按方块的世界坐标算。`/xjy capture` 抓的鲸图在 `Metadata.Xiaojingyu.Origin` 里记了站立点，第 (0,0,0) 格的世界坐标 = `Origin` + `Offset`（docs/FORMAT.md §3.2），所以从抓来的鲸图画出来和游戏里一样（P3-001、P3-002 都是这样比的）；没有 `Origin` 的文件（别的工具存的 `.schem`、手写的 JSON）就当第 (0,0,0) 格在 `Offset`，形状、颜色都对，只是贴图朝向和草的位置会和原来的世界不同。
11. **只做主世界白天晴天**：雾、天空色按主世界白天算；下界、末地、雨天、夜里不对。网页背景是透明或自己的渐变，没有天空、云、太阳。
12. **没 jar 时**：按名字分大类给我们自己的颜色、像素纹理和简单形状，和 MC 只是「大概像」。木结构带板缝/木纹，两格门分别画上下凹板；灯笼有底座、顶盖、提环、吊链和暖色灯体。贴图经同一个带边距/mipmap 的图集路径处理。已有 jar 模型始终优先，原创纹理只服务缺模型兜底；房屋灯笼夜间自发光强度为 0.65，保留灯芯细节和独立照明灯光。找不到模型的方块（模组方块、拼错的名字）也用这个兜底，并在提示里列出来，不画 MC 那种紫黑格子。
13. **没做的小东西**：滴水石锥的随机偏移、模组 jar 里的模型（现在只读 `assets/minecraft/`）、方块实体的 NBT（告示牌的字、旗帜的图案等）。

## 8. 页面、体积、建议

- **14–19 不进 home**：`web/build.mjs` 的 home 排除规则里有 `1[4-9]-`（lead 改的），home 页不带这些模块（构建日志里 home 是 modules=49）；studio、cabin、mcview 还带。14–19 加起来约 132 KB 源码（14-mcjar 18.8 KB，15-mcmodel 19.0 KB，16-mcmesh 48.5 KB，17-mcfallback 16.8 KB，18-mcthree 9.2 KB，19-mcentity 10.6 KB，19-mclight 12.3 KB）。加载时只是在 `V3` 上定义函数和表（Node 里量约 1.8 ms），不碰 IndexedDB、页面、网络、全局事件，没有定时器，也不创建 three.js 对象；IndexedDB 只在调用 `V3.mcjar.cacheSave/cacheLoad/cacheClear` 时才打开，现在只有 mcview 调。
- **查看页不进发布包**：`web/tools/release.mjs` 只打 studio、cabin、home；mcview（`src/92-mcview.js`，13.9 KB；整页 0.84 MB，不内嵌 `assets/`）只给开发和对比工具用。
- **世界坐标不加新字段**：用 `Metadata.Xiaojingyu.Origin` + `Offset`（第 6 节第 10 条）。

建议（由 lead 定）：

- 以后要在 cabin/home 里给玩家看 MC 方块时，再把 14–19 放进 home，并把 mcview 里「选 jar、忘掉 jar、打开鲸图」这几样做成正式界面；mcview 的地址参数和 `window.__mcview` 只给工具用，不要给玩家。
- 方块实体还剩告示牌、旗帜、头颅、潜影盒等（第 7 节第 3 条），做法和箱子、床一样：照 MC 的实体模型自己写盒子组，从 jar 读 `textures/entity/` 下对应的贴图。

## 10. 工作台模型「小屋 v4 方块草图」（P4，`src/43-house-mc-model.js`）

给用户在工作台（studio.html，反馈工具）里看「用原版 MC 方块重做的小鲸鱼之家」（2026-11-06 起是用户选定的定稿：方案 B、一楼净高 3 米、两色屋顶、平滑石英、屋脊盖板；模型名字还叫「方块草图」）。房子的方块数据是 fmt-js 的 `src/42-house-mc.js`（`V3.houseMc`，说明在 docs/HOUSE-V4.md），这个模块只管把它画出来、接到反馈工具上。游戏页的房子不用这个模块：`src/54-house-mc.js` 直接读内嵌的鲸图 `assets/house/house-v4.png` 来画（同样用 16-mcmesh，但不乘 MC 的朝向明暗，交给场景的太阳和灯去照；见 docs/HOUSE-V4.md 第 15 节）。home 不加载 42、43（web/build.mjs 的排除规则），cabin 只是模型列表里多一项。

- **打开**：工作台模型列表选「小屋 v4 方块草图」，或者地址 `studio.html?model=housemc`。视角和 house2 一样有 hero、house、inside、loft、top、site。
- **开关**（工作台右边的下拉框，也能写进视角口令）：`plan`（方案；定稿后 42 只给一项 b，开关留着，键名不叫 variant，因为 `variant` 已经是 56-furn-ground.js 的视角口令）、`roof`、`wall`（42 给的材料小样，没有就不显示）、`floor`（外观 / 一楼 / 阁楼：按 42 的 `levels`，把这层顶 `y1` 以上的格子换成空气）、`furniture`（占位盒子显示 / 不显示，不用重建）、`tex`（MC 贴图 / 我们自己的颜色）。方案和材料开关的初始值用 42 的 `V3.houseMc.DEFAULTS`（方案 b、两色屋顶、平滑石英）；没有 DEFAULTS 时用名单第一个。
- **贴图**：读 `V3.mcjar.cacheLoad()`，也就是在 MC 方块查看页（mcview.html，同一个网址下）选过一次的 jar；工作台里没有选 jar 的按钮。没有缓存时用第 2 节的兜底颜色，并提示一次「去『MC 方块查看』页选一次 jar」。
- **部件**：按 42 的 `parts`（每格一个相对路径，比如「墙/南墙」「屋顶/北坡」）把网格拆开：每个面算到「面中心往里退一点」所在的那格，归给那格的部件；一个部件一个 three.js Group，挂在「方块小屋/…」下面，反馈工具里能点选、能隐藏、树里有中文名（42 的 `labels`）。家具是半透明橙色盒子 + 描边，挂在「方块小屋/家具/…」，42 给了说明的带在名字后面（如「厨房台面（缩短到 3.6 米，给楼梯口让路）」）；看一楼时不显示阁楼的家具。
- **画法**：和查看页同一套网格（第 3、4 节：面剔除、AO、正午光照），一张图集、四层材质，只是不加雾。光照照现在这样，不追求和游戏一样亮（用户定的）。房子放在场景里：格子 (0,0,0) 的位置 = `Origin + Offset`（第 2 节「输入格式」），地上一块示意的沙地（点不到）。
- **异步**：网格是异步建的，模型对象有 `ready`（Promise，每次改开关换一个）。`V3.view` 和 studio 开页时都会等 `ready`（`V3.waitReady`，src/00-core.js，最多 10 秒，超时或失败记一条中文错误后照常继续），所以 `__READY` 时房子已经画完，反馈里存的视角重放也会等它。
- **没有 42 时**：用 43 里自己的假房子（`H.fakeHouse`，同样的接口，只用来开发和测试）。
- **截图**（开发用，真贴图的图只放 tmp/mc-render/）：`node tmp/mc-render/shoot-housemc.mjs --jar <MC 客户端 jar> --compare --floors --mats` → tmp/mc-render/housemc-shots/：每个方案（现在只有 b）× hero / house / top、一楼和阁楼剖面、和 house2 同视角并排（compare-*.png）、第一个方案的屋顶 × 墙面小样（mats-house-*.png），约 10 秒。
- **已知的小问题**：一楼剖面里「一楼/吊灯」挂在阁楼地板下面，切掉上层后看着像飘着；家具只是盒子；沙滩、海、植物不画方块；没贴图时的颜色是我们自己定的大类颜色。
