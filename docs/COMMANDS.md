# 小鲸鱼之家 · 命令约定（P2）· 第 1 版

> 这是 lead 写的约定，做模组命令的子智能体照它做；要改先找 lead。文件格式见 `docs/FORMAT.md`，API 笔记见 `docs/NEOFORGE-26.1-API.md` §5、§6、§10。

`/xjy` 的命令都在服务器上执行（单人游戏就是内置服务器），需要权限等级 2（和 `/fill`、`/clone` 一样：单人游戏要开作弊，服务器上要是管理员）。

## 1. 朝向、站立点、坐标

- **站立点 S**：玩家脚所在的那一格，`player.blockPosition()`。
- **朝向**：玩家水平朝向，`player.getDirection()`（只取东南西北，抬头低头不算）。前方向量 F：北 (0,0,−1)、南 (0,0,1)、东 (1,0,0)、西 (−1,0,0)；右手向量 R = F 顺时针转 90°（俯视）：北→东、东→南、南→西、西→北。
- 旋转：顺时针 90° 记作 k=1，和 MC 的 `Rotation.CLOCKWISE_90`、`BlockPos.rotate` 一样：`(x, y, z) → (−z, y, x)`。

## 2. `/xjy capture`

写法（四种；没写的数字用「抓取范围配置」里的，见下面）：
- `/xjy capture`：4 个数都用配置里的。
- `/xjy capture <前> <左右> <高>`、`/xjy capture <前> <左右> <高> <名字…>`：这 3 个用写的，**往后用配置里的**（配置是默认的 0 时和以前完全一样）。名字是最后一个参数，可以有中文和空格，不用加引号；3 个数字后面的都是名字，名字以数字开头也没关系（`/xjy capture 3 2 3 7 号房` 的名字是「7 号房」）。
- `/xjy capture 范围 <前> <后> <左右> <高> [名字…]`（英文 `range`，2026-11-07 mod6 加）：4 个数都用写的，不看配置。用字面量开头，所以和上面那种不会混：`范围` 后面正好 4 个数字，再后面的都是名字。
- `/xjy capture 上次 [名字…]`：见 §2b，不管范围配置。

范围（默认 前 16、后 0、左右 8、高 12）：
- 前：从面前那一格算起往前 `前` 格（玩家自己站的这一列不算在「前」里），1–64。
- 后（2026-11-07 用户定的，mod6）：**从玩家自己站的这一列算起往身后** `后` 格，0–64。0 = 身后不抓（以前的样子）；1 = 只多抓自己站的这一列；7 = 自己这一列 + 身后 6 列。盒子前后一共 `前 + 后` 格。用途：站在台阶前面朝房子时，往后调到 7 左右，普通 capture 就能把身后的沙滩休闲角一起抓进来。
- 左右：左右各 `左右` 格（两边一样），宽 = 2×左右+1，0–64。
- 高：**从脚下那一层（S.y − 1，也就是脚踩的地面）开始**往上 `高` 层，1–64。默认 12 = 地面 + 往上 11 层。
- 用局部坐标 (f, s, u)：f = 1−后…前，s = −左右…+左右，u = −1…高−2；世界坐标 = S + f·F + s·R + u·(0,1,0)。取这些格子的最小角和最大角就是抓取的盒子。`Offset` 照常 = 最小角 − S（往后不是 0 时，朝北站的话 Offset 的 z 不变、盒子往南多出去；朝东时 Offset 的 x 变成 −(后−1)）。
- 最大的盒子：129 宽 × 64 高 × 128 长 = 1,056,768 格（§3 的 place 上限跟着改成这个数，抓得出来的都能盖回去）。
- 参数出界（Brigadier 的整数范围，命令失败）、盒子超出世界高度（主世界 −64…319）、盒子里有区块没加载 → 拒绝，不写文件，聊天栏说明原因。

抓取范围配置（用户 2026-11-07 定的，mod6 实现）：
- 4 个数（往前、往后、左右、往上）存在 NeoForge 的模组配置里：`ModConfigSpec`，COMMON 类型，文件 `<游戏目录>/config/xiaojingyu-common.toml`（开发游戏是 `mod/run/config/`，专用服务器在服务器目录的 `config/` 里）。整个游戏一份，所有存档共用（和黑名单一样）。没有文件时游戏启动就按默认值写一个。
- 键：`captureFront`（1–64，默认 16）、`captureBack`（0–64，默认 0）、`captureSide`（0–64，默认 8）、`captureUp`（1–64，默认 12）。都在顶层，不分节。文件里每个键上面有中文和英文的说明、默认值和范围（NeoForge 自己加的 `Default:`、`Range:`）。
- 界面：游戏主菜单或暂停菜单 →「模组」→ 小鲸鱼之家 →「配置」，直接打开「小鲸鱼之家：抓取范围」这一页（只有一个配置文件，NeoForge 自动跳过选文件那一步）：4 个滑块（往前几格、往后几格、左右各几格、往上几层，鼠标停在名字或滑块上有一句说明和取值范围），下面「抓取黑名单 [打开…]」，最下面「取消」（撤回这次的改动）、「重置」（4 个都回默认值）、「完成」。是 NeoForge 自带的配置界面（`ConfigurationScreen`），带范围的整数（最大 − 最小 < 256）它自己就画成滑块。
- 生效：拖滑块马上改内存里的值（单人游戏下一次 capture 就按新的抓），点「完成」时写进文件。用记事本改文件也行：NeoForge 盯着这个文件（`fml.toml` 的 `disableConfigWatcher = false`，默认就是），保存后大约 1 秒自己重读，不用重启、不用重进世界；写了超出范围的数会被改到最近的界上（比如 100 → 64），写坏了（不是 TOML）就按默认值重写；这两种情况 NeoForge 都先把原来的文件备份成 `xiaojingyu-common-1.toml.bak`。
- 「抓取黑名单 [打开…]」：等于输入 `/xjy blacklist`（发给服务器，服务器发回名单、打开 §2a 的界面），黑名单界面点「完成」回到这一页。只在进了世界、服务器装了这个模组、有权限（等级 2，单人游戏开作弊）时能点；不能点时按钮是灰的，鼠标停上去说为什么。点之前这一页改过的先写进文件。
- `/xjy status` 多一行：现在不写数字的 capture 用的 4 个数，和等价的 `/xjy capture 范围 前 后 左右 高`（§4a）。
- 专用服务器：COMMON 配置**不同步**（NeoForge 的规矩）。服务器上 capture 用的是服务器自己 `config/xiaojingyu-common.toml` 里的数，服主改那个文件（改完自己重读）；玩家的配置界面改的是玩家自己电脑上的文件，只管自己的单人游戏。连着别人的服务器打开配置界面时，最下面多一行黄字「这里改的不管服务器」（鼠标停上去有说明）。玩家用 `/xjy status` 能看到服务器现在用的数。
- 代码：`build/CaptureRange.java`（4 个数、上限、盒子，纯计算）、`config/CaptureConfig.java`（ModConfigSpec、登记、`current()`）、`client/CaptureConfigScreen.java`（NeoForge 配置页的子类，加黑名单按钮和服务器提示），`client/XiaojingyuClient.java` 登记 `IConfigScreenFactory`。

存什么（FORMAT.md 第 1 版）：
- 每一格都存，**包括空气**（盖回去时空气会清掉原来的东西，这样才「一模一样」）。下面「黑名单和液体」里说的几种方块例外，按换过的存。
- 方块状态用 `BlockStateParser.serialize`；方块实体用 `saveWithoutMetadata(level.registryAccess())`（不含 id 和坐标），箱子里的东西也存（权限等级 2 的工具，和 `/clone` 一样会复制物品，写进文档）。
  - 相册矮桌的整本相册、相框和画框墙里的照片也在方块实体里，一起抓、一起盖（docs/PHOTOS.md 第 2 节，2026-11-08 mod7）。这三种空的时候方块实体是 `{}`（不写 MC 默认的空 `components`），和网页写的一样。
- 实体（画、物品展示框、盔甲架、生物）**不抓**，写进已知问题。
- `Offset` = 最小角 − S；`DataVersion` = 当前游戏的数据版本。
- Metadata：`Name` = 给的名字（去掉首尾空格；没给就是 `capture-年月日-时分秒`，本地时间）；`Author` = 玩家名；`Date` = 现在的毫秒数；`Xiaojingyu`：`FormatVersion` 1、`Facing` = 抓取时的朝向、`Origin` = S、`Dimension` = 维度 id、`Source` = `xiaojingyu-mod/<模组版本>`、`GameVersion` = 当前 MC 版本。

文件：
- 放在 `<游戏目录>/xiaojingyu/`（`FMLPaths.GAMEDIR`）。用户的启动器开了版本隔离时，游戏目录是 `.minecraft/versions/<版本名>/`；开发游戏里是 `mod/run/xiaojingyu/`；专用服务器上在服务器目录里。没有这个文件夹就建。
- 文件名 = 名字 + `.png`：`\ / : * ? " < > |` 和控制字符换成 `_`，去掉末尾的空格和点，最长 64 个字符，空了就用默认名；Windows 保留名（CON、PRN、AUX、NUL、COM1–9、LPT1–9）前面加 `_`。重名就加 `-2`、`-3`……，**不覆盖**已有文件。
- PNG 的图片部分是预览图（见第 5 节），数据在 `xjSc` 块里。
- 读世界、编码、压缩、写文件都在命令执行时、在服务器线程上一次做完（65×64×64 实测 35 ms；加了往后以后最大 1,056,768 格，按比例约 70 ms，和原版大的 `/fill` 差不多；实测超过 250 ms 再改成后台写）。先写到临时文件再改名，不会出现写了一半的文件。命令结果（result）= 非空气格子数；命令成功就表示文件已经完整写好。

聊天栏（成功）：抓了多大（W×H×L）、多少个非空气方块、多少个方块实体、文件名（点一下复制完整路径：服务器发的消息不能用「打开文件」，客户端不认，按源码确认）；再加一句「发给别人时请发原图或当文件发，聊天软件压缩图片会把数据弄丢」。

黑名单和液体（用户 2026-11-07 定的，mod4 实现）：
- **抓取黑名单**里的方块（§2a）当空气存。名单记的是方块 id，这个方块的所有状态都算（比如名单里有 `minecraft:oak_stairs`，各个朝向、含不含水的橡木楼梯都当空气）。模组自己的家具也能加。
- **液体**一律当空气存：水、岩浆（源头的和流动的，`LiquidBlock`，别的模组的液体方块只要是 `LiquidBlock` 也算），还有气泡柱。
- **含水的方块**（有 `waterlogged=true` 的楼梯、半砖、栅栏、告示牌、箱子、灯笼……）留下方块，存成 `waterlogged=false`。
- 海草、高海草、海带这类本身是方块的植物照常存（它们里面也有水，但它们是方块）；不想要可以加进黑名单。
- 换过的方块，后面的一切都按换过的算：非空气格子数（命令的 result）、方块实体（当空气的就不存它的方块实体）、预览图（当空气的格子看下面一格的颜色）。
- 名单文件读不出来（坏了）时照样抓，按空名单算，聊天栏多一句黄色的提醒（原因、文件在哪）。
- 有方块被换掉时，聊天栏多一句：按名单当空气的几格、液体当空气的几格、去掉水的含水方块几个。
- 只在抓取时换，世界里的方块不动。`/xjy place` 不管名单，文件里是什么就放什么。
- 判断规则写在 `build/CaptureFilter.java`（按 `BlockStateParser.serialize` 的字符串判断，cmdTest 能测）；`command/Capture.java` 再把结果换回 BlockState 用来算预览图颜色和方块实体。

## 2a. `/xjy blacklist`（抓取黑名单）

用户 2026-11-07 定的，mod4 实现。和别的 `/xjy` 命令一样要权限等级 2。

写法：

| 命令 | 做什么 | result |
| --- | --- | --- |
| `/xjy blacklist` | 玩家：打开名单界面（见下面）。控制台、命令方块：和 `list` 一样 | 名单里几种 |
| `/xjy blacklist add <方块>` | 加一种方块。Tab 补全方块 id（空气、水、岩浆、气泡柱不列）；可以不写 `minecraft:` | 加完名单里几种 |
| `/xjy blacklist add` | 加准星对着的那块（就是有黑框的那块，在交互距离内，看穿液体） | 同上 |
| `/xjy blacklist remove <方块>` | 删一种。Tab 补全名单里已有的 | 删完还剩几种 |
| `/xjy blacklist remove` | 删准星对着的那块 | 同上 |
| `/xjy blacklist list` | 在聊天栏列出名单（最多 30 行，点一行把删除命令填进聊天栏）和名单文件的路径（点一下复制） | 几种 |
| `/xjy blacklist clear` | 清空 | 删掉了几种 |

- 改完马上生效（下一次 capture 就按新名单），聊天栏说清楚做了什么、名单里现在几种；改动也像 `/gamerule` 一样告诉别的管理员、写进服务器日志。
- 失败（success = false，什么都不改）：不是方块 id；这个游戏里没有这个方块；空气、水、岩浆、气泡柱（本来就当空气，不用加）；remove 的不在名单里；不带方块名时准星没对着方块；名单文件存不进去。
- 已经在名单里再 add：成功，名单不变，result 照样是几种。名单本来是空的再 clear：成功，result 0。

名单文件：
- 整个游戏一份，所有存档共用：`<游戏目录>/config/xiaojingyu-blacklist.json`（开发游戏是 `mod/run/config/`，专用服务器在服务器目录的 `config/` 里）。名单在服务器那边；客户端只显示服务器发来的名单。
- 一开始没有这个文件，就是空名单；第一次改名单时才写出来。
- 格式（UTF-8，人可以用记事本改）：

```json
{
  "note": "小鲸鱼之家：用 /xjy capture 抓鲸图时，blocks 里列出的方块都当空气导出。……",
  "blocks": [
    "minecraft:stone",
    "xiaojingyu:dining_table"
  ]
}
```

- 读的时候宽松：只写一个列表 `["minecraft:stone"]` 也行；可以不写 `minecraft:`；大写会变小写；写成方块状态（`minecraft:oak_stairs[facing=north]`）按整个方块算；记事本加的 BOM、`//` 和 `#` 注释、多出来的逗号都不要紧；重复的算一个。不是方块 id 的项跳过（日志里记，`list` 和打开界面时聊天栏提一句），其余照用。这个游戏里没有的方块 id（比如卸掉的模组的）留着，只是不起作用，`list` 里标「这个游戏里没有这种方块」。最多读 4096 项。
- 每次用名单（抓取、各个 blacklist 命令、打开界面）之前看一眼文件的大小和修改时间，变了就重新读，所以用记事本改完保存就生效，不用重进世界。
- 文件坏了（不是 JSON，或者既不是列表也没有 `blocks` 列表）：不崩，按空名单算；日志里记一行，`list`、打开界面、抓取时聊天栏用黄字说哪一行附近有错、文件在哪。这时在游戏里改名单（add、clear）会先把坏文件原样复制成 `xiaojingyu-blacklist.json.bak`，再写新文件，所以写过的东西不会丢。
- 写文件时先写临时文件再换掉原文件。Windows 上偶尔会因为别的程序（比如杀毒软件）正开着这个文件而换不了：重试几次，还不行就直接写进原文件；再写不进去，这次改动撤销，命令失败。

界面（`/xjy blacklist`）：
- 也能从 模组 → 小鲸鱼之家 → 配置 那一页的「抓取黑名单 [打开…]」打开（§2「抓取范围配置」，2026-11-07 mod6 加：它就是替你发 `/xjy blacklist`），这时点「完成」回到配置页。
- 上面是名单：每种方块一个格子（图标、名字、id），两列，多了用滚轮翻。点一下就从名单里删掉。没有物品的方块（比如高海草）图标是问号。
- 左下是玩家的物品栏（36 格，和背包一样排）：点一个方块物品就加进名单。不是方块的物品变暗，点了没反应；已经在名单里的方块描黄边。鼠标停上去有说明。
- 右下是输入框：输入方块 id，回车或者点「加进名单」；输入时灰色字提示补全，按 Tab 补上。下面是「完成」。
- 每次点击只是发包请服务器改（`BlacklistNet.Edit`），服务器检查权限和 id、改名单、写文件，再把新名单发回来（`BlacklistNet.Sync`），界面上显示一句结果（绿字成功、红字失败），聊天栏里也记一句。名单变了的时候，所有有权限的玩家打开着的界面都会更新。不暂停游戏。
- 专用服务器上也一样能用（名单在服务器上）。界面的类在 `com.xiaojingyu.client` 包里，只由 `dist = CLIENT` 的入口加载，专用服务器不会碰到；cmdTest 的 ClientSplit 检查别的包没有用到客户端的类。

## 2b. `/xjy capture 上次`（按上次 place 的盒子抓）

用户 2026-11-07 定的，mod5 实现。用途：网页的房子是一张鲸图，盖进 MC 改了以后要原样抓回去；按 §2 的写法只抓面前一块，站偏一格整栋就错位，院子也抓不全。

写法：
- `/xjy capture 上次`、`/xjy capture 上次 <名字…>`。英文写法一样：`/xjy capture last [名字…]`。名字的规矩和 §2 一样（最后一个参数，可以有中文和空格）。

记录（「上次放的」）：
- `/xjy place` **放完**（status 回到 0、聊天栏说「放好了」）时记一条：文件名、维度、站立点 S'、盖的人当时的朝向、转了几度（`auto` 算出来的或者写的 0/90/180/270，以及当时写的是 auto 还是数字）、文件里的 Offset、Size、Facing（没有就不记）、盒子（世界坐标）、时间。中途停下的（区块没加载、出错）不记。
- 按玩家（UUID）记，每人最近 5 条（和撤销一样多），存在**存档**里：`<存档>/data/xiaojingyu/last_place.dat`（游戏自己的 SavedData，自动保存、退出世界时保存），所以退出世界再进来、服务器重启都还在。不同的存档各记各的；一个存档里所有维度共用一份。
- `/xjy undo` 撤掉某次 place 时，那次的记录一起删掉，「上次」回到再前一次（都撤完了就没有「上次」）。服务器重启后撤销记录没了（§4），但「上次」还在，这时 capture 上次 抓的就是最后一次放完的。
- capture（包括 capture 上次）不改记录。

抓法：
- 不管玩家现在站在哪、朝哪、在哪个维度，都按记录里的盒子抓（读那个维度）。
- 抓出来的鲸图和当初放的那张文件**同样大小、同样 Offset、同样 Facing、同样朝向**：文件的格子 (x, y, z) 当初放在 `S' + 转k(Offset + (x, y, z))`，抓的时候就从那一格读回来；方块状态按 `state.rotate` 转回去（转 −k：楼梯、门、床、家具的 facing，栅栏、玻璃板的连接都跟着转回去；门的合页、床和家具的 part 不变）；方块实体数据原样。所以 place 时转过 90°，抓回来也是原文件的摆法，网页拿到的和原文件逐格对得上。
- §2「黑名单和液体」照样起作用（名单里的、水、岩浆、气泡柱当空气，含水的去掉水）。
- 预览图按文件的摆法画（文件里的北朝上），不是世界里的北。
- Metadata：`Name` = 给的名字；没给就是「原文件名去掉扩展名 + `-年月日-时分秒`」（比如 `house-v4-b-20261107-121530`；原文件名后面已经有这样的时间就换掉，不叠）。文件名照 §2 的规矩，不覆盖已有文件。`Author`、`Date`、`Source`、`GameVersion` 照 §2，`Dimension` = 记录里的维度。`Facing` = 原文件的 Facing（原文件没有就不写，auto 盖回去也不转）。`Origin` = 当初 place 时的站立点 S'。另外多一个 `Xiaojingyu.FromPlace`：`{File: 原文件名, Turn: 当初转了几度}`（FORMAT.md §3.1）。
- result = 非空气格子数，和 §2 一样；聊天栏和 §2 一样，多一句「这是按上次放的 X 抓的（当时站在哪、转了几度，现在转回去了）」。

失败（success = false，不写文件）：
- 这个玩家在这个存档里没有「上次」（没 place 过，或者都撤销了）：「还没有用 /xjy place 放过鲸图……先 place 一张，改完再 capture 上次」。
- 这个玩家的 place / undo 还没放完（和 place 一样的「上一次还没放完」）。
- 记录里的维度现在没有（比如卸掉了加维度的模组）。
- 盒子里有区块没加载（人走远了）：「上次放 X 的地方离你太远……走近一点再抓」；超出世界高度照 §2。不为了抓去加载区块。

## 3. `/xjy place <文件> [转向]`

- `<文件>`：`xiaojingyu/` 文件夹里的文件名，可以不写扩展名（先找 `.png` 再找 `.schem`）。不能带路径：有 `/`、`\`、`:`（盘符）或控制字符就拒绝，整个参数是 `.` 或 `..` 也拒绝；名字中间有 `..`（比如 `a..b.png`）可以，网页下载来的文件常有这种名字。找到的必须是 `xiaojingyu/` 下面直接的普通文件：拼出路径后规范化，确认它的上一级就是 `xiaojingyu/` 文件夹本身，路径不合法（Windows 不认的名字）也当作找不到。名字里有中文或空格要用英文双引号括起来；按 Tab 列出文件夹里的文件，补全时自动加引号。
- `[转向]`：`auto`（默认）、`0`、`90`、`180`、`270`。数字是相对文件里原来的摆法顺时针转多少度；`auto` = 从文件的 `Facing` 转到盖的人现在的朝向（文件没有 `Facing`，比如 WorldEdit 的文件，就当 `0`）。
- 位置：盖的人的站立点 S'，每一格放在 `S' + 转k(Offset + (x, y, z))`；方块状态用 `state.rotate(Rotation)`；方块实体数据原样放到转过的位置。**同一地点、同一朝向、auto 盖回去，就和抓的时候一格不差。**
- 放的时候：
  - 所有格子都放，包括空气。
  - 先检查调色板里每个状态在这个游戏里都认得（`BlockStateParser`）。有不认得的 → 整个不放，聊天栏列出前 3 个，并按调色板算出可能缺的模组。
  - 超出世界高度、有区块没加载、超过 1,056,768 格（就是我们自己抓的最大的盒子 129×64×128；以前是 1,048,576，2026-11-07 加了往后以后跟着改大，抓得出来的都能盖回去）→ 不放，说明原因。
  - 文件读不出来 → 显示 FORMAT.md §5 的中文提示（没有数据块时那句「请发原图」很重要）。警告 `data_version`、`newer_format` 照样放，但在聊天栏提一句。
  - 读文件、解析、上面这些检查都在命令执行时一次做完（数据块最大 16 MiB，读加解析几十毫秒）；有问题命令就失败（success = false），一格都不放。检查通过后命令成功，result = 要放的格子数，同一个 tick 开始放第一批。
  - 放法是两遍。第一遍原样放状态（不按邻居重算形状、不掉落、不触发方块实体的副作用、不调 `onPlace`；有方块实体的格子照 `StructureTemplate` 先放屏障、再放真方块、再读入数据），同时记下撤销快照。第二遍只管盒子外面：盒子表面上真的变了的格子，让贴着它的盒外方块按新邻居重算形状，并收到「邻居变了」（红石、门会有反应）；盒子里面的格子不再收任何更新。结果要求：盒子里每一格的状态和文件里的一样（盒子边上的方块也不会改去连外面的东西）；盒子外贴着的方块（比如栅栏、红石）按新邻居正常更新。已知的代价：盒外隔一格的比较器读不到盒子里容器的变化；被拆掉的拉杆隔两格的强充能不刷新（旁边动一下方块就好）。不照 `FillCommand` 那样给盒子里每一格都发更新，因为那样盒子里的红石线、门、带水的方块会按新环境改状态，做不到一格不差。
  - 大的分几个 tick 放：每 tick 一批（先定 8192 格，实测后调，目标是不让服务器一个 tick 超过约 50 ms），每 2 秒左右给这个玩家发一次进度，放完再发一句「放完了」。进度和「放完了」只发给玩家本人（下线了就不发），不算命令输出，所以卡片要用 `/xjy status` 的 result 等到 0，不要看聊天文字。放的过程中这个玩家再 place 或 undo → 拒绝「上一次还没放完」。玩家中途退出也继续放完。
  - 放的过程中盒子所在的区块不能被卸载：放之前给这些区块加一张临时的加载票，放完（或服务器停止）就撤掉。万一还是有格子所在的区块没加载，就停下这次放置，已经放了的留着（撤销记录照样能撤），告诉玩家。不在服务器线程上同步硬加载区块。
  - 文件超过 64 MiB 直接报 too_large，不读进内存（xjSc 数据块本身最大 16 MiB，见 FORMAT.md §1；预览图可以比较大）。
- 成功：放了多少格、用了多久，提示可以 `/xjy undo`。

## 4. `/xjy undo`

- 每个玩家记最近 5 次 place（只在内存里，服务器重启就没了，写进已知问题）。
- 一次 place 的撤销记录 = 放之前那个盒子的快照（和抓取一样：每格状态 + 方块实体），加上维度和位置。撤销 = 把快照原样放回去（同样两遍法，不洒箱子里的东西），然后从记录里删掉。
- 撤销会把那个盒子整个恢复到 place 之前，place 之后在盒子里做的改动也会没了（写进文档）。
- 撤销一开始就把那次 place 的「上次放的」记录（§2b）删掉，`/xjy capture 上次` 回到再前一次放完的。
- 拒绝：没有可撤销的、正在放、那一块的区块没加载。
- capture 不改世界，不进撤销记录。没有「重做」。
- 和 place 一样：检查在命令执行时做完，失败就 success = false；成功时 result = 要恢复的格子数，之后分 tick 放。

## 4a. `/xjy status`

- 只读，不改任何东西。聊天栏说：现在有没有正在放（或撤销）的、放到多少了；最近一次 capture 的文件名；上次放的（§2b：文件名、站在哪放的、转了几度、盒子从哪到哪，就是 capture 上次 要抓的那块；不在玩家现在的维度时加上维度名；没有就说一句要先 place）；还能撤销几次；不写数字的 capture 现在用的范围（§2「抓取范围配置」：往前、往后、左右、往上，里面写了等价的 `/xjy capture 范围 前 后 左右 高`（英文 range），两种语言都有这 4 个数连着写，卡片 P2-006 靠它等配置文件重读完；在服务器上就是服务器的配置）。
- result = 这个玩家还没放完的格子数，0 = 空闲。卡片用它等 place / undo 放完。

## 5. 预览图

- 俯视图：每一列从上往下找第一个地图颜色不是 `NONE` 的方块，用它的地图颜色（`state.getMapColor(level, pos)`，抓取时从世界里算）；按高度深浅变化（像原版地图那样，比北边那格高就亮、低就暗）。整列都是空气 → 透明。
- 每格 s×s 像素，s = 1…16，让长边不超过 512 像素。上方是北。
- PNG 编码自己写（`java.util.zip.Deflater` + CRC32），不用 ImageIO、不用客户端的 NativeImage（专用服务器上没有）。

## 7. 验收（P2）

用探针卡片（`docs/PROBE.md`）在开发世界里自动做，卡片放 `mod/cards/P2-*.yml`。卡片缺的步骤（比如「记下一块区域」「和记下的比」「检查文件存在」）可以加到 `mod/tools/lib/cards.mjs`，同时更新 `docs/PROBE.md`「卡片格式」和 `mod/tools/test/`。

2. 转向：在别处朝东 place（auto，顺时针 90°）→ 尺寸长宽对调，抽查的楼梯、门、床的朝向按顺时针转了，箱子里的东西还在。

4. 两边互通：capture 出来的 PNG 用 `node web/tools/share.mjs dump` 读，结果和探针读到的盒子一致；把网页写的 `fixtures/share/js/p0-blocks.png` 复制进 `mod/run/xiaojingyu/`，place 之后探针读到的和 `fixtures/share/cases/p0-blocks.json` 一致。
5. 坏文件：place 一张普通 PNG → 命令失败（success = false）；中文提示里有「原图」由第 6 节的小测试检查。
6. 原有的都还过：`gradlew build`（含 shareTest）、`node --test mod/tools/test/*.test.mjs`、P0-001 卡片。

卡片注意：开发世界会重复用，`xiaojingyu/` 里的文件不会自动删，重名会变成 `-2`；卡片里的文件名要每次不一样（比如带上这次运行的编号），或者开始前先清掉自己上次的文件。等 place / undo 放完用 `/xjy status` 的 result 等到 0。
