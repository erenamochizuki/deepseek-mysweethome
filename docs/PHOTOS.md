# 相册和相框（第 6 件，2026-11-07 起）

用户原话（2026-11-07）：「画框这个，不知道可不可以改成类似地图或者展示框的机制呀，就是网页里是我们可以往相册里传图片（会被压缩到一定尺寸），然后导入游戏的时候就用这个机制让相册中的图片在游戏里也可以显示。」

用户定的（2026-11-07 21:55）：
- 照片压到 **128 × 128**（和 MC 的地图一样大）。
- **新加一种单个的相框**（1 格，像展示框一样挂在任何墙上，想挂几个挂几个）；西墙那件**画框墙的 6 个小框也能放照片**。
- **MC 里能换照片**：整本相册跟着房子进 MC（存在相册矮桌里），在 MC 里右键相框换成相册里的下一张；抓回网页时换过的也带回来。

这份文件是网页（web7）和模组（mod7）共用的约定。改约定先问 lead。

## 1. 照片

- 正方形 128 × 128，PNG，不透明（RGB 或者 alpha 全是 255 的 RGBA），一张最多 48 KB：**写的一方不超过 48000 字节，读的一方接受到 49152 字节（48 × 1024）为止**（2026-11-08 lead 定，网页和模组都按这个）。
- 网页上传：从中间裁成正方形，高质量缩到 128 × 128，存成 PNG；超过 48 KB 就减少颜色再存。
- 一张照片在 NBT 里是一个 compound：

| 键 | 类型 | 说明 |
|---|---|---|
| `Id` | string | PNG 字节的 SHA-1，取前 16 个十六进制字符（小写） |
| `Png` | byte array | PNG 文件的全部字节 |
| `Name` | string，可选 | 名字（上传时的文件名去掉扩展名，最多 64 个字） |
| `Added` | long，可选 | 加进相册的时间（毫秒） |

- 读的一方都要先查：`Png` 以 PNG 文件头开头、宽高都是 128、不超过 48 KB，不对就当这张没有（不崩、不画），日志里记一行。MC 客户端在解码之前也要先这样查（照片可能来自别人分享的鲸图或多人服务器）。

## 2. 方块实体（鲸图 `BlockEntities` 里 `Data` 的键就是这些，docs/FORMAT.md §3.3）

| 方块 | 方块实体 id | 键 | 发给客户端 |
|---|---|---|---|
| 相册矮桌 `xiaojingyu:photo_album_table` | `xiaojingyu:photo_album_table` | `Album`：照片的 list，最多 64 张，顺序就是相册里的顺序 | 不发（客户端不需要；同步时给空的） |
| 相框（新）`xiaojingyu:photo_frame` | `xiaojingyu:photo_frame` | `Photo`：一张照片；没有这个键 = 空相框（显示衬纸） | 发 |
| 画框墙 `xiaojingyu:picture_frames` | `xiaojingyu:picture_frames`，只放在 `part=0` 那格 | `Slots`：6 个元素的 list，每个是一张照片或者空 compound（空 = 显示原来的小画） | 发 |

- 鲸图的 capture / place / capture 上次 都把方块实体的数据原样带着（P1、P2、§2b 已经是这样）。
- 网页的默认房子里相册是空的，6 个小框都是原来的小画。

## 3. 照片画在哪（photoSlots）

- 只有 export 工具（`node tools/furn-mc.mjs export`）写 `FurnitureShapes.java`。工具给有照片的家具生成：
  - `Kind.photoSlots()` → `double[][]`（2026-11-07 22:20 lead 同意从 int 改成 double：画框墙的画布在半像素上），每行 `{part, x0, y0, x1, y1, z}`：在**朝北的模型**里、相对这一格（part）的像素坐标，`x0..x1`、`y0..y1` 是照片那块的矩形，`z` 是那块画布的面在模型里的深度（像素，朝北的模型正面朝 −z）。
  - 相框 1 行；画框墙 6 行，行号 = 第 2 节 `Slots` 的编号 = 网页 56-furn-ground 里 `FR` 的顺序（canvas0..5）。
- 网页的规格（web/src/44-furn-mc.js）里也有同样的数（`photoSlots`），网页按它贴照片。以 FurnitureShapes.java 为准。
- 两边一样的画法（web7 提、lead 同意）：
  1. `z` 是模型里那个面的位置（不含偏移）；画的一方自己往 −z（正面）挪 0.01 像素，免得闪。
  2. 照片正着贴：从正面看（朝北的模型，人站在北边往南看），照片左边在 `x1`、右边在 `x0`、上边在 `y1`。
  3. 矩形不是正方形时（画框墙的画布是横的长方形），照片从中间裁成矩形的比例再贴（像 CSS 的 `object-fit: cover`），不拉伸。
  4. 跨两格的矩形（画框墙中间上下两幅跨了 part 0 / part 1）：`part` 取矩形中心所在的那格，坐标相对那一格，可以超出 0..16（比如 x −4..4.5）。
- 新相框是整数：照片 2..14 × 2..14。画框墙 6 行（朝北模型，export 写好后以 FurnitureShapes.java 为准）：`{1, 6.5, 1, 15, 6, 15.5}`、`{1, -4, 1, 4.5, 6, 15.5}`、`{0, 1, 0.5, 10.5, 6.5, 15.5}`、`{1, 6.5, 8.5, 15, 13.5, 15.5}`、`{1, -4.5, 8, 5, 14, 15.5}`、`{0, 1.5, 8.5, 10, 13.5, 15.5}`。

## 4. MC 里（mod7）

- 相框、画框墙、相册矮桌注册成带方块实体的家具方块（其余照 FurnitureShapes）。
- 右键相框（空手，或者拿着不是方块的东西）：换成相册里的下一张。潜行右键：上一张。
  - 相册 = 同一维度里离这个相框最近的相册矮桌（16 格以内）的 `Album`。
  - 现在这张按 `Id` 在相册里找：找到就换下一张；找不到就换第一张；最后一张的下一张是空。
  - 潜行右键（上一张）：找到就换上一张；第一张的上一张是空；现在是空的或者找不到就换最后一张（lead 2026-11-07 同意）。
  - 附近没有相册矮桌、或者相册是空的：聊天栏（动作栏）说一句。
  - 画框墙：按点到的位置找是哪一个框（photoSlots）。
- 渲染：方块实体渲染器，照片做成动态贴图（按 `Id` 缓存，没人用时释放），画在 photoSlots 的矩形上。
- 照片发给客户端时只发相框、画框墙的；相册矮桌不发。

### 4.1 怎么用（MC 里）

- **照片从哪来**：在网页里往相册里加照片，导出房子的鲸图，在 MC 里 `/xjy place` 盖出来。相册存在相册矮桌里，跟着房子一起进 MC；相框、画框墙里已经放好的照片也一起进来。
- **换照片**：站在相框前面，空手右键（手里拿着不是方块的东西也行，比如木棍、吃的），就换成相册里的下一张。物品栏上面那行字会说「第 2 / 5 张照片：名字」。
- **往回翻**：按住潜行（Shift）再空手右键，换成上一张。潜行的时候手里不能拿东西：MC 原版的规矩是「潜行又拿着东西时右键不碰方块」。
- **顺序**：空 → 第 1 张 → 第 2 张 → … → 最后一张 → 空 → 第 1 张……，一直转圈；潜行就倒着转。新相框空的时候露出衬纸，画框墙的小框空的时候是原来那幅小画。相框里的照片如果不在相册里了（比如网页里删了），右键换成第 1 张，潜行右键换成最后一张。
- **画框墙**：6 个小框各换各的，点哪个框就换哪个；点到框和框之间的木头上，换离点到的地方最近的那个。
- **用哪本相册**：同一个世界（主世界、下界各算各的）里离这个相框最近的那张相册矮桌，16 格以内。附近没有：会说「附近 16 格里没有相册矮桌」；相册是空的：会说「相册是空的」。右键相册矮桌会说相册里有几张照片。
- **手里拿着方块右键相框**：和平常一样放方块，不换照片。
- **新相框**：在创造模式物品栏「小鲸鱼之家」那一页的最后。像展示框一样，对着墙的侧面放，它就贴在那面墙上；放在地上或者天花板上时，它朝着你。
- **抓回网页**：`/xjy capture`、`/xjy capture 上次` 抓出来的鲸图带着整本相册和每个框现在的照片，网页导入以后就是在 MC 里换过的样子。
- **拆装相册矮桌**：有正常掉落的拆除会把整本相册保留在掉落物的引用里，同一世界再放下就恢复；创造模式 Ctrl＋中键复制也保留。每张放下的桌子独立编辑，改一张不影响另一张或已有物品。空桌掉普通物品；创造模式直接拆掉没有掉落，仍按原版规则。
- **跨世界与备份**：引用依赖原存档的相册快照，复制背包物品到别的世界不会把照片带过去。找不到快照时会提示并拒绝放置，物品保留；跨世界请用带完整照片的鲸图 capture / place。备份应包含整个世界存档。拆掉相框，那张照片还在相册里；用 `/xjy place` 盖错了可以 `/xjy undo`。
- 多人游戏里别人也看得到照片，照片跟着存档存。

### 4.2 做法（mod7，2026-11-08）

- 方块：这三种是 `PhotoFurnitureBlock`（`FurnitureBlock` 的子类，加了方块实体和右键），样子、碰撞、放法和别的家具一样；方块实体类型 id 和方块 id 一样，画框墙只有 `part=0` 那格有。新相框例外的一点：点墙的侧面时朝着离开墙的方向（`getClickedFace`）。
- 存：读进来的 `Album` / `Photo` / `Slots` 原样存回去（坏照片也原样留着，只是不显示、翻页时跳过），所以 capture 抓回去的和放进来的一样。空的时候整个方块实体就是 `{}`：MC 默认会写一个空的 `components: {}`，这三种不写（和网页的默认房子一样）。
- 检查：服务器读方块实体时、客户端收到时、解码之前，都按第 1 节查（PNG 文件头和 IHDR、128 × 128、不超过 49152 字节（读的一方的上限））；不合规的当没有，日志一行 `[xiaojingyu] … photo … skipped (not_png, …)`。`Id` 没写就按 PNG 算一个（存的数据不改）。相册最多读前 64 张。
- 发给客户端：相框、画框墙只发合规照片的 `Id` 和 `Png`；相册矮桌不发。换照片、`/xjy place`、`/setblock` 时马上发（每个方块实体一个包，最多 6 × 48 KB）。进世界、走近时的区块包里，每个区块的照片最多 1 MiB（按位置先后算），多出来的方块实体在这个区块发完以后各自单独发：PNG 压不小，联机时一个包压缩后超过 2 MiB 会断线，这样一面墙挂满照片也不会。
- 画：方块实体渲染器（26.1 的写法见 docs/NEOFORGE-26.1-API.md §15）。照片按 PNG 字节的 SHA-1 做成贴图 `xiaojingyu:photo/<id>`（Id 写错了也不会显示成别的照片），同一张照片好几个框共用一张；每帧最多新解码 4 张；30 秒没画到就释放，退出世界全部释放。按第 3 节的 4 条画法贴在 photoSlots 的矩形上，像展示框里的地图一样受方块光照、没有方向阴影，另外加了深度偏移，远处也不闪。
- 测试：`gradlew cmdTest` 的 Photos 组（照片检查、翻页、4 个朝向点画框墙）；卡片 P5-004（`node mod/tools/photo-card.mjs` 生成）。

### 4.3 拆装持久化（2026-11-09）

- `AlbumSnapshot` 是不可变的整本原始 `Album` 快照，包括照片顺序、名字、时间和坏照片；compound 的键排序后算 SHA-256，list 保留原顺序。相同内容复用同一快照。
- 快照统一存在主世界 SavedData，类型 `xiaojingyu:albums/<64位hash>`；磁盘路径为世界的 `dimensions/minecraft/overworld/data/xiaojingyu/albums/<hash>.dat`。由原版存档生命周期保存、压缩写盘；所有维度的物品都从这个库恢复。快照不自动回收，因为物品可能还在箱子、离线玩家或未加载区块中。
- 物品只带 `xiaojingyu:album_reference` 数据组件（64 位小写十六进制字符串，网络内容为 65 字节），不带整本 PNG。普通掉落、爆炸幸存掉落共用 `getDrops`；掉落条件仍由原掉落表决定。Ctrl＋中键通过隐式组件收集引用，并从 `block_entity_data` 去掉原始 `Album`，避免一件物品带近 3 MiB。
- 放置前查引用和内容哈希；缺失或损坏则不放、不消耗。放置时把原始 Album 深拷贝进新方块实体并消费隐式组件，方块实体继续保存完整 Album；编辑后再次拆下生成新快照。capture / place 的完整 Album 格式不变，网页导入导出也不变。
- Java Photos 组覆盖 64 × 49152 字节、压缩 NBT 文件写盘重读、嵌套数据深拷贝、哈希规范化、非法引用以及 65 字节网络组件。真实 SavedData 缓存清空与重读由 MC 卡 P5-006 覆盖，不把纯 NBT 写盘测试当作重进世界测试。
- `node mod/tools/album-carry-card.mjs` 生成 P5-006（`--check` 检查最新）；卡片放入 64 张小 PNG，检查真实掉落、背包携带、实际放置/消耗、Ctrl＋中键小于 1024 字节且无 Album、复制后单独改名、退回标题重进后恢复全列表、空桌、缺失引用不消耗。完整容量的 PNG 字节预算在 Java 测试覆盖；MC 卡由 lead 统一运行。
- 开发探针新增 `POST /pick {pos:[x,y,z],includeData:true}`：要求创造模式与正常交互距离，走原版服务器的 pick packet 处理，返回 `{item,reference,hasAlbum,encodedBytes}`（最后一个是整件物品 SNBT 的 UTF-8 大小，用于卡片上界断言）。`POST /world/reopen {}` 只能重进本探针进程最后一次 `/world/open` 创建的世界，不接受外部存档路径；先 `/world/leave` 并等标题，再 reopen 并等 inWorld。两者只在开发探针里，发布 jar 不包含。

## 5. 网页里（web7，2026-11-08 做好）

### 5.1 怎么用（网页里）

**相册**

1. 游戏页（`cabin.html` / `home.html`）左下角切到「阁楼」，点相册矮桌（坐垫北边的小圆桌），打开相册。
2. 「＋ 添加照片」选照片（可以一次选好几张），或者直接把照片拖进相册的窗口。每张从中间裁成正方形，缩到 128 × 128（和 MC 的地图一样大），存成 PNG；颜色太多、存出来超过 48 KB 的会减一点颜色。同一张不会加两次；不是图片、浏览器打不开的会说清楚是哪张。
3. 点一张照片选中，窗口下面一条可以：改名字（最多 64 个字，回车或者点别处就存）、「← 往前」「往后 →」调顺序、「删除」（点两下）。相册最多 64 张，满了「添加照片」就点不了。
4. 每次修改会随房屋一起存档（本机服务版存到服务端，独立网页存到浏览器），房子变成「布置过的房子」（和布置模式一样，设置「房子」页能看到；「恢复原来的房子」会连相册一起清掉）。「导出鲸图」时相册跟着房子带进 MC。
5. 删掉相册里的照片，已经挂在相框上的不会跟着没了（相框里存的是自己的一份）。

**挂照片**

1. 一楼西墙那组画框（画框墙）的 6 个小框和新的「相框」都能挂照片。游戏里直接点那个框（看外观时也行，只要没被墙挡着），打开「换照片」。
2. 挑相册里的一张就挂上；挑「空」就取下来（相框露出衬纸，画框墙露出原来的小画）。窗口里「打开相册」可以先去加照片。
3. 照片从离这个框最近的相册矮桌里挑（16 格以内，和 MC 里一样）。附近没有相册矮桌、或者相册是空的，窗口里会说，只能选「空」。
4. 画框墙的小框是横的长方形：照片从中间裁成那个比例贴上去，不拉伸（第 3 节）。

**新的相框**

1. 左下角「布置」→「加家具」→「屋里」那页最后一个「相框」，点一面墙挂上（和画框一样挂墙，背后要是墙），想挂几个挂几个。
2. 布置模式里选中相框（或者画框墙），小按钮下面多一个「换照片」；画框墙先在窗口上面点要换的那个小框。这样换的照片算布置模式的一步：能「撤销一步」，「完成」才存，「放弃修改」就不要了。
3. 布置模式里挪相框、挪相册矮桌、挪 / 转整栋房子，照片都跟着走；拆掉就没了（拆了马上「撤销一步」能回来）。
4. 布置模式里打开相册只能看，不能改（点「完成」退出布置以后再改）。

**房子里没有相册矮桌**：相册窗口会说「这栋房子里没有相册矮桌」，照着说的在「布置」→「加家具」里放一张，「完成」以后再点它。

### 5.2 照片的检查和坏照片（网页这边）

- 网页自己存的照片都不超过 48000 字节（48 KB 按 1000 还是 1024 算都不超）；读别人的（MC 抓回来的、别人分享的鲸图）时按 48 × 1024 = 49152 字节算。
- 读到的照片不是 PNG、不是 128 × 128、超过 48 KB、`Png` 不是 byte array，都当没有：相框、画框墙上不画（画框墙露出原来的小画），浏览器的控制台里记一行。头对但解不开的也不画。导入这样的鲸图照样能用，导入后提一句「有 N 张照片坏了」。
- 相册里网页打不开的照片不显示，相册窗口里说一句；改相册的时候它们原样留在相册最后，网页不删。画框墙别的小框里的也原样留着。
- 方块实体的 `Data` 是 `{}`、没有 `Album` / `Slots` / `Photo` 键、`Slots` 不够 6 个，都当空的。网页写的时候：空相册不写 `Album`；`Slots` 一定写满 6 个（空的是空 compound）；别的键原样带着。布置模式里新放的相册矮桌、相框、画框墙（part=0 那格）带一条空的方块实体（`Data` 是 `{}`），拆了就删。
- 照片纹理按 PNG 字节的 SHA-1 缓存（`Id` 写错了也不会显示成别的照片）。

### 5.3 代码和测试
