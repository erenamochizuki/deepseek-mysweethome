## 2. 方块状态（模组、网页、生成器、转换工具都照这个）

- 都有 `facing`（north / south / east / west）。模型按「正面朝北」做（正面在 −z），blockstate 用 y 旋转：north 0、east 90、south 180、west 270（和 MC 的炉子、箱子一样）。
- **床** `xiaojingyu:bed[facing=…,part=head|foot]`：和原版床一样，`facing` 是从床尾指向床头的方向，床头格 = 床尾格 + facing。玩家放的是床尾那格（站在床尾后面朝床头的方向放）。
- **餐桌** `xiaojingyu:dining_table[facing=…]`：单格。
- **贝壳柜** `xiaojingyu:shell_case[facing=…,part=left|right]`：`facing` 是正面朝的方向；`left` / `right` 是**站在正面前、看着它**时的左 / 右。右格 = 左格 + （facing 逆时针转 90° 的方向）。例：facing=east（正面朝东）→ 人站东边往西看，左手是南，所以 left 在南边（z 大），right = left + 北。
- 两格的家具：放下时两格都放；拆掉任一格，另一格一起消失，掉一件物品（照原版床的做法）。另一格没有了就不合法（`/shapes` 会把它算成空气），所以鲸图里两格要一起写。
- 不含水，不发光，不挡光（noOcclusion），木头的声音、硬度和木板一样。
- 碰撞 / 选框：每格用模型在这一格里所有方块（element）的外包盒（按格子分开），随 facing 转。

## 4. 体素 → Blockbench → MC 的管线（furn，2026-11-06）

```
web/src/56-furn-ground.js、57-furn-loft.js（体素家具，真代码）
   │  bb：取体素 → 换成朝北的 MC 坐标 → 按格子切开 → 合成长方块（一格超过 32 个的简化到 32 以内，第 10 节）→ 颜色烘进贴图
   ▼
models/furniture/<id>.bbmodel（Blockbench 5 的 java_block 工程；模型的源头，用户可以在 Blockbench 里改）
   │  export：每格一个方块模型 + blockstate + 物品 + 贴图 + 碰撞盒
   ▼
mod/src/main/resources/assets/xiaojingyu/{blockstates,models,textures,items}/   和   mod/src/main/java/com/xiaojingyu/furniture/FurnitureShapes.java
   │  build.mjs 打进网页（lead）
   ▼
游戏页、工作台里的方块房子（54-house-mc）；开发 MC / 玩家的 MC（模组 jar）
```

规格是 `web/src/44-furn-mc.js` 的 `V3.furnMc`（纯数据，Node 里也能读）：每件的 id、方块名、中文名、布局里的 id、`rot`（体素转成朝北模型要转多少度）、`align`（在格子里居中还是贴背面）、`facing`（和体素版摆法一样的朝向）、`size`、`cells`（朝北时每格相对主格的位置和 part）、`models`、贴图名；贝壳柜还有 `slots` / `slotSize`（朝北、主格 left 的方块内坐标，单位格；1 格 = 1 米）。小函数：`byBlock`、`byId`、`byLayout`、`cellsFor(f, facing)`、`state(f, facing, part)`、`rotate`、`rotatePoint`。

### 4.1 bb：体素 → .bbmodel（`web/tools/lib/furn-mc-vox.mjs`、`furn-mc-bb.mjs`）

1. **取体素**：在 Node 里跑网页的真代码（`V3.furn.buildAll`，工作台「家具一览」的样子），把建家具时用到的体素网格都拿到。只要默认样子：床是 made 那一套（叠好的睡衣 + 第二只枕头），sleeping 的被窝曲面不要。
2. **换坐标**：体素 1 格 = 1/32 米 = 半个 MC 像素。按 `rot` 转（床 0；餐桌、贝壳柜 180：正面从 +z 转到北边），再平移到格子里：x、z 居中时往 +x / +z 偏 1/4 像素（1/64 米），这样所有边都正好在半像素上，格子的分界也正好在体素的缝上；贝壳柜贴着背面（靠墙）。脚底就是方块底。
3. **斜着的、更细的体素**（床上的睡帽：转过、缩过，每格 1/58 米）按 1/32 米重新取样（每格 27 个点，过 3 成算有）。
4. **超出格子的体素裁掉**，`bb` 和 `info` 会报出来。
5. **合成长方块**：每格分开合（每格一个 group，名字 = part，单格的叫 `main`）；同一个部件（体素的 tag，比如「床架」「床垫」）、同样透明度的才合在一起，element 的名字就是部件名。每个起点试 6 种「先往哪个方向长」，取体积最大的；整格再试 3 种扫描顺序，取方块最少的。颜色不影响合并（颜色在贴图里）。
   **这样合出来一格超过 32 个元素的，交给「简化」**（`web/tools/lib/furn-mc-lite.mjs`，第 10 节）：不分部件、合得粗一点，直到 ≤ 32；不超过的格照上面的做法，一个字节都不变。
6. **面**：一个面整面都被别的体素挡住（不透明的，或同一种玻璃）就不要；否则在贴图里占一块。贴在方块底上的面也留着（导出时带 cullface，下面是实心方块就不画）。简化过的格的面另外算（第 10.2 节：往里第一个体素的颜色，整列空的像素透明）。
7. **贴图**：32 像素 / 格，一个体素的面 = 一个像素。像素颜色 = 体素颜色 × 体素版的明暗噪点 × 体素版的 AO（四个角的平均，和 03-vox.js 一样的算法），在线性空间里乘。玻璃的像素半透明（体素版玻璃的不透明度 0.3）。每块四周留一圈延伸的边，块的起点、大小都是偶数（远处 mipmap 时不串到旁边那块的颜色）。贴图的宽高是 16 的倍数。

### 4.2 export：.bbmodel → MC 资源（`web/tools/lib/furn-mc-export.mjs`）

- **方块模型**（每格一个，`models/block/<模型>.json`）：group 里的元素减去这一格的位置，坐标 0..16，朝北；**不引用原版父模型**，`textures` 里 `"0"` 和 `particle` 都是这件的贴图。uv 换成 MC 的 0..16。贴在方块边上的面自动加 cullface（不用 Blockbench 里设的）。元素的旋转、inflate、shade、发光、面的旋转、tint 照搬；不是方块元素的（mesh）跳过并提醒。
- **blockstate**：`facing × part` → 模型 + y 旋转（north 0、east 90、south 180、west 270）。
- **物品**：`items/<id>.json`（26.1 的物品定义：`{"model":{"type":"minecraft:model","model":"xiaojingyu:item/<id>"}}`）→ 物品模型 `models/item/<id>.json`：整件（所有格拼在一起，x、z 居中到 8），display 照原版方块的，按大小缩（床、贝壳柜缩到 2/3，物品栏里看着和一个方块一样大）。
- **贴图**：从 .bbmodel 里取出来，按我们的 PNG 编码器重新写（字节稳定）。
- **FurnitureShapes.java**：每件每个 part 一组盒子 `{x0, y0, z0, x1, y1, z1}`（朝北、像素、每格自己的 0..16），现在每格一个盒子 = 这一格元素的外包盒。`boxes(id, part)`、`rotateY(box, quarterTurns)`、`quarterTurns(facing)`；不用 MC 的类（接口说明见 `tmp/furn/shapes-api.md`，mod 的 `FurnitureCollision` 按这个读）。
- 同样的 .bbmodel 导出几次都一模一样；`check` 在内存里重新导出和仓库里的比（文本文件不管换行是 LF 还是 CRLF）。导出管的目录里多出来的文件也算不一样。

### 4.4 第 2 轮多出来的（2026-11-07）

- **规格**（44-furn-mc 的 `kind()`）：part 是整数（8.1：`part = cx + w × (cz + d × cy)`，主格 part 0），单格的没有 part；模型 `xiaojingyu:block/<id>`（单格）或 `<id>_<part>`；`house` = 房子里的摆法（和 42-house-mc 的 `V3.houseMc.FURN2` 一样，测试对）；`collide`（每格 box / thin / none）、`light`、`overlay`（网页要叠的网格名：`pc-screen`、`bulb`、`screen`、`rice`）、`planes`（体素版里不转 MC 的平面：屏幕、画布）、`extra`（合进来的别的体素家具：地毯 + 小茶几）、`also`（同一种的另一件：两把餐椅）、`voxRect`（转 MC 时换的矩形：串灯只取一段）、`repeat`（串灯一排 12 格）。小函数多了 `collideOf(f, part)`。
- **「场景」换法**（furn-mc-vox.mjs 的 voxelsScene，有 `house` 的都走这条）：体素版照 40-layout 摆好（buildAll 的位置、朝向、高度），每个体素中心从场景坐标换到朝北、主格的本地格子：north (x−x0, z−z0)、south (x1+1−x, z1+1−z)、east (z−z0, x1+1−x)、west (z1+1−z, x−x0)，再 `floor(× 32 + 1e−6)`。所以体素在格子里的位置就是 40-layout 的位置（靠墙的贴墙），不用 align。每个轴只对着一个轴的直接换（压扁的地毯、地垫也行），转过的（望远镜、睡帽）重新取样。第 1 轮的 3 件还是原来的换法（rot + align），.bbmodel 不重做。
- **合元素**：一格超过 200 个元素时不分部件再合一次（大盆栽 199、懒人沙发 194）。
- **物品模型**：整件超过 3 格（厨房台面 4 格长）时，先把元素绕中心缩进 MC 允许的 −16..32（MC 不认超出的元素），display 再按缩过的大小算。
- **FurnitureShapes.java**：第 1 轮的具名常量不变；第 2 轮每种一个 `Kind`（w、d、h、light、每格 collide、碰撞盒 boxes、选框 outlines、placeholder），`KINDS`、`kind(id)`、`Kind.part / cell / offset`。选框每格都是模型外包盒（none 的格也有，不然点不中、拆不掉）。接口说明 `tmp/furn/shapes-api.md`。
- **体素版改的**（56 / 57 / 57-loft2 的 build 函数，40-layout 的矩形，见第 6 节的表）。

### 4.5 第 3 轮多出来的（2026-11-07，屋外的 15 种）

  比 1/32 米细的体素（饮料 1/128 米）：每个目标格子里过 1/20 才算有、取最多的颜色；粗的（遮阳伞 1/16 米）一个填 2×2×2 格；转过的（躺椅靠背）重新取样。

- **preview**：第 3 轮的体素版从场景部件里取（预览页多加载 50-scene、55、56-furn-beach、58），带 `place` 的按 Node 算好的矩阵摆，和 MC 版都在房子里的位置；地板在方块底。

### 8.1 通用约定（新家具都照这个；床、餐桌、贝壳柜照第 2 节不变）

- 状态：`facing`（north / south / east / west），占不止 1 格的再加 `part`（整数 0..N−1，MC 的 IntegerProperty）。不加别的属性。
- `facing` 是正面朝的方向（坐下的人脸朝的方向、柜门朝的方向；挂墙的是离开墙的方向）。和网页体素版 REG 里的 `face` 一样（s / e / n / w）。
- 格子：模型按朝北做（正面在 −z）。朝北时家具占本地格子 cx = 0..w−1（往 +x，东）、cz = 0..d−1（往 +z，往后）、cy = 0..h−1（往上）。`part = cx + w × (cz + d × cy)`，主格是 part 0（朝北时正面、最西、最下那格）。
- 朝别的方向时，本地格子跟着模型一起顺时针转：east：(cx, cz) → 世界 (−cz, +cx)；south：→ (−cx, −cz)；west：→ (+cz, −cx)。都相对主格。
- 两格以上的：放的时候所有格一起放，放不下就放不了；拆任何一格，整件都没了，只掉 1 件物品（主格掉）；某一格的邻格不对（不是同一件、facing 不同、part 不对）就变成空气，连锁到整件（和床一样，`/shapes` 能查出来）。
- 碰撞（规格里的 `collide`）：`box`（按模型每格的外包盒，默认）、`thin`（贴地 1/16 格，人能走上去：地毯、地垫）、`none`（没有碰撞：画框、调料罐架、串灯）。
- 光：规格里的 `light`（0..15），会亮的才有。

## 10. 简化：每格 ≤ 32 个元素（furn4，2026-11-07）

用户 2026-11-07：「cube 太多 MC 负担不了，风铃那种（每格 27 个）完全没问题，遮阳伞那种太多」，建议排查现有模型、简化（比如遮阳伞直接简化成多层的立方体）。上限：**每个方块模型（每格）最多 32 个元素**。

### 10.1 定的

- 只简化老做法（第 4.1 节）合出来超过 32 个元素的格：25 件、33 格。别的 15 件（木箱灯笼 32、相册矮桌 32、窗边坐垫 31、书桌椅、床头柜、串灯、风铃、餐椅、调料罐架、画框、壁灯、坐垫、毛巾、两块地垫）**.bbmodel 和导出的东西一个字节都不变**（测试查）。
- 每格的碰撞种类（box / thin / none）、光不变；碰撞盒、选框照样由 export 按元素的外包盒算，简化只会让它往里缩、每边不超过 1 像素。实际只有两件变了：懒人沙发顶低 0.5 像素、门廊的蕨四周各小 1 像素（最外面的叶尖），别的都一样。
- 体素版（工作台的家具一览、转模型的源头）不改；网页游戏里的家具跟着变（同一份 MC 模型）。规格（44-furn-mc）没加字段。
- 40 种一共 3743 个元素 → 1601 个。

### 10.2 做法（`web/tools/lib/furn-mc-lite.mjs`，`bb` 时自动做）

1. **分种类**：透明度（玻璃单独）× 分组。受保护的分组不合、不删，元素原样留着：
   - `solid` 的部件（遮阳伞的伞杆：碰撞只算它，别的元素可以盖住它）；
   - `glow` 的部件（发光的灯罩）、`overlay` 里网页要叠上去的骨骼（台灯的灯泡、串灯的灯泡）：别的元素不许盖住它们。
   - 不许盖的地方（keepOut）：overlay 里默认看不见的骨骼（空碗里的米饭）那块空着的格子、屏幕面板前面那层空着的格子；不许删的（pinned）：屏幕面板。
2. **先精确合**：不分部件，和老做法一样「每个起点试 6 个方向长」，够 32 个就停（双人小沙发、电视柜、储物箱就是这样，样子一点没变）。
3. **不够就贪心**，每一步挑「每少一个元素代价最小」的一下：
   - **合两块**成它们的外包盒，代价 = 多盖进去的空气（体素个数）；外包盒里不许有别的种类的体素；顺手吞掉被它整个包住的同种块；
   - **删一块**，代价 = 只有它盖着的体素 × 6 − 只有它盖着的空气（丢东西比多点空气难看：试过 × 3，摇椅的弧形底座、望远镜的腿、花箱垂下来的藤、鲸鱼抱枕的尾巴会被删掉；× 6 都留住了）；
   - 删了以后整格的外包盒每边不许缩超过 2 个体素（1 像素），碰撞不变小。
   直到 ≤ 32。不同的块可以重叠（合出来的外包盒），重叠的地方两块的贴图取的是同一个体素，颜色一样，不闪。
4. **面的贴图**（细节画进贴图）：一个像素 = 从这个面往里走、碰到的第一个同种体素的颜色（× 明暗噪点 × AO，和老做法一样，32 像素 / 格）；**整列都没有体素的像素透明**（alpha 0）。
   所以合起来的块里原来空着的地方看过去还是空的：椅背栏杆之间的缝、花丛和叶子的空隙、伞面圆边外面的四个角、高低不齐的书顶上。
   MC 26.1 按每个面自己那块贴图有没有透明像素自动放进 cutout 层（`FaceBakery.computeMaterialTransparency` → `SpriteContents.computeTransparency(u0, v0, u1, v1)`；半透明的进 translucent），**不用写 render_type**；网页 14-mcjar 的 `spriteTransparency` 一样。
   面外面贴着别的不透明体素、并且那个体素有元素盖着的像素算「看不见」，整面看不见的面不要。
5. **元素名** = 这块里最多的那个部件（Blockbench 里看，一个元素可能盖着好几个部件）。
6. **屏幕对齐**（`snapScreens`，新做法所有格都做）：体素换到 MC 格子时取整，原来电脑屏的平面陷在 MC 的玻璃里 0.24 格（7 毫米，网页叠上去的屏幕画面被挡住）、电视屏的平面浮在面板前面 0.56 格（17 毫米）。
   现在屏幕面板那块元素的正面挪到平面后面 2 毫米，穿过平面的边框（电脑屏左边那一列）退到平面的边上；只挪几何，贴图不变。
7. **花草**：本来打算做成原版花草那样的交叉面片（两片竖着交叉、厚度 0、透明贴图）。试下来上面的通用做法 + 透明贴图已经和简化前几乎一样（垂藤、链子成了带透明缝的薄片，花丛成了几层），面片反而会稀、只剩两个方向，就没做。
   **遮阳伞**也没手工做：伞面自然合成了一层一层的方块、一层比一层小，红白条纹在贴图上，圆边外面的角透明，所以还是圆的（就是你说的「多层的立方体」）。

`bb` 的 `makeBb(f, { lite: false })` = 老做法（简化前）；预览图的「简化前」那排就是这样在内存里重新生成的，不用存旧文件。

这 10 个 `.bbmodel` 是源件，可直接在 Blockbench 编辑；整件内每个顶层组仍对应一个方块格。用 `node tools/furn-mc.mjs export` 导出，`node tools/furn-mc.mjs check` 核对 229 个资源与形状文件。批量 `bb --force` 会保留已有的手工件；只有显式指定单件 ID 加 `--force` 才会用旧体素覆盖，**正常编辑不需要这样做**。重建网页与模组后两端使用同一份模型与贴图。

`npm run test:furn` 包括 41 件 × 4 个朝向、物品模型、UV、碰撞与选框，以及新模型的共面检查。共面检查在元素旋转之后比较朝向和四边形的实际重叠面积，不把相邻部件接边算成闪烁。可用 `MC_JAR` 指向 26.1.2 客户端以核对原版与模组资源的合并加载。此次还用该客户端自身的 `CuboidModel.fromStream` 读取了 64 个方块模型和 41 个物品模型，并在实际小屋页面的 16 个移动视角检查了悬停描边。

另在本地运行 Blockbench 5.2.2 的原生工程读取器，逐一打开全部 41 份 `.bbmodel`：方块的起止坐标及旋转、分格数量、内嵌贴图尺寸均与源件一致。测试未向外部服务上传工程。
