# 小鲸鱼之家：转动镜头后悬停高光闪烁

**状态：已修复并应用到本机，用户已确认问题消失。** 修复版本：`v3-20261115-2305-79af76d`（小鲸鱼之家）。

## 现象与定位

转动镜头后，鼠标停在望远镜等交互物体上，物体表面出现跳动的亮斑或亮边，几秒后稳定。固定选中的望远镜、冻结角色和天气动画，只让相机扫过 16 个微小角度，仍能复现。这说明即使拾取目标没变，渲染也会闪烁；主场景和描边使用的是同一帧的相机，并不是描边落后了几帧。

## 根因

部分家具使用单独生成的模型副本来画悬停轮廓。副本与原模型使用不同的局部坐标原点，转成 Float32 顶点后，两者几乎共面，但算出来的深度不总是相同。

旧实现把原模型和描边副本画进同一张深度缓冲。相机在拖动结束后仍有微小的缓动，在不同帧里，原模型会盖掉副本的不同像素，使描边掩膜出现空洞。合成时，空洞边缘又被误认成轮廓，所以亮边出现在物体表面。扩大掩膜采样只能遮掉细缝；加大深度偏移则可能让高光穿过墙或被子。

## 修复

在 [08-hover-outline.js](<../src/08-hover-outline.js>) 里，先画一张**场景深度图**（不画仅用于描边的副本），再单独画**选中物体的掩膜和深度图**。合成时比较同一像素的两份深度：用很小的视空间容差吸收共面舍入误差，真正位于墙面或其他遮挡物之后的像素仍不画高光。保留源材质原有深度偏移，不再人为把选中物体拉到前面。鼠标拾取、点击、镜头阻尼和存档逻辑均不变。

## 验证和复查

- [GPU 动态回归](<../test/hover-outline-stability.test.mjs>) 在独立参考轮廓的内部计数：同样 16 个角度，旧版每帧误画 **27–2,314** 个像素，修复后 **0–1** 个；前景挡板完全挡住时漏光 **0**。
- 在更新后的本机页面上用 Edge 实际拖动镜头，悬停望远镜后连续 52 帧保持提示和描边，移开鼠标后正常清除。后期处理开/关两条渲染路径的回归均通过，仓库审计 130/130。
- 如再遇到类似问题：先看**提示是否随整个描边一起消失**，再固定目标扫角度。如果只在物体内部跳，优先检查掩膜和深度；不要先加悬停延迟或凭单张静态截图判定已修复。
